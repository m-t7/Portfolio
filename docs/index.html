I'm a computer science student with a focus in software engineering: building applications end to end, from data structures and database design through APIs, front-end interfaces, and security. This ePortfolio highlights three artifacts that show that range: a simple Java service, a C++ console application and a full-stack web app.

Collaboration

Enhancing the Travlr Getaways application for CS 465 meant reading an existing codebase's route handlers, models, and components carefully before changing anything, the same discipline required when joining a team mid-project rather than building alone from scratch. Consolidating the public-facing site and the admin dashboard onto one shared framework, React with Vite and Tailwind CSS, instead of the original Handlebars and Angular split, was itself a collaboration decision: developers working on either app now share the same tooling, component patterns, and conventions instead of having to context-switch between two different frameworks, which makes it easier for a team to move between the two apps or review each other's work.

Communication

In CS 305, I worked with a simulated client, Artemis Financial, assessing the security of their RESTful API and reporting what I found. Turning a static analysis report full of vulnerability details into a set of prioritized, actionable recommendations taught me how to communicate technical findings in terms a client can act on, not just a list of flaws. Each artifact in this portfolio carries that same habit forward: a plain-language README written for a reader who won't open the source file, aimed at the same audience a stakeholder update is written for.

Data Structures and Algorithms

The CS 300 course planner is the clearest evidence here. The original version stored courses in a binary search tree; I replaced it with an unordered_map for constant-time course lookup, added a discipline index for faster searching, and implemented a breadth-first search to traverse prerequisite chains. That same habit, matching the structure and algorithm to the operation a program actually performs, shaped the query patterns behind the CS 320 contact database and the Travlr trip lookups too.

Software Engineering and Databases

CS 320 and CS 465 show the same discipline at different scales. CS 320 pairs a validated Contact model with a SQLite-backed service layer and a JUnit suite covering every CRUD path. CS 465 scales that up to a full architecture: an Express/Node API backed by MongoDB, consumed by two React front ends. Modernizing it, replacing legacy Handlebars and Angular with a shared React/Vite/Tailwind stack, taught me to refactor a working system without breaking its contract with its consumers.

Security

Security shows up as a design constraint, not an afterthought. The CS 320 database layer builds every query with parameterized statements, closing off SQL injection at the source. In CS 465 I found and removed a stored XSS surface that existed in both the original Handlebars template and the original Angular admin app, each rendering trip descriptions as raw HTML, and carried the app's existing JWT authentication forward into the new React admin app so protected endpoints still reject unauthenticated requests instead of trusting the client.
